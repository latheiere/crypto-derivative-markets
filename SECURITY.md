# Security policy

## Supported releases

Security fixes are provided for the latest released minor version. Before the stable `1.0` release,
upgrading to a newer minor version may require an API migration; wire compatibility remains governed
by explicit schema identifiers.

## Reporting a vulnerability

Use the private security-reporting feature of the public source repository. Do not open a public
issue for a vulnerability that could affect package consumers or the release pipeline.

A useful report identifies the affected version and reusable triggering condition, explains impact,
and includes the smallest safe reproduction. Do not include live credentials, private catalog data,
or concrete production identifiers.
